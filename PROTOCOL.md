# Study 45: Forecast transfer after a simulated cache-capacity change

## Decision and acceptance

Does a linear miss-fraction forecast selected under one simulated LRU capacity retain its accuracy after a capacity change, compared with a previous-block baseline? The deliverable is a bounded trace-replay benchmark and offline configuration-review exercise. The original proposal mentioned operational configuration changes and systems ML. These traces contain recorded storage requests, not observed cache interventions. Here interventions are authored simulations conditional on a fixed request sequence. Forecast units are misses per 1,000 recorded requests, not clock-time IOPS, latency, throughput, production hit rate, energy or savings. Preserve the original proposal and distinguish source facts from simulation.

Acceptance: fixed source rights/cohort/bounds before values; exact private complete compressed objects and safe hash/header receipts; independently reconstructed public ordinal request prefixes; strict future-field exclusion; complete qualification; independent exact LRU block counts and independently checked regression/selection/metrics; all settings, failures and group results; committed dependency freeze before all final-volume simulation/features/scores; meaningful fixtures and offline exercise; source-preserving two-runtime full-history replay; three source-bound inspected figures and a rendered measured manuscript; scoped publication audit; exact candidate/main Linux CI, matching tree, remote annotated tag and accurate program metadata. Passing these finite criteria earns 4/5, not novelty, universal software correctness or operational reliability. At most three substantive review rounds, forty-five active review minutes and sixty review-specific calls; acquisition/execution separate. Unknown required gates prevent a release claim.

## Bounded acquisition and public projection

Fetch each of six exact documented objects once, no redirect. At most seven GET attempts including one global targeted 429 retry, honor Retry-After with fallback at least sixty seconds, preserve failures; repeated denial/challenge/auth error stops dependent acquisition. At least two seconds between GET starts. Forty MiB per decoded HTTP object and 160MiB total, exact expected metadata length and ETag required. Save complete compressed objects privately, UTC start/end, safe headers and local SHA256; S3 multipart ETag is not a SHA256 or universal checksum. Incomplete transfers stay separately retained, never zero data or silently resumed across different entities.

Decode only the first 200,000 complete 24-byte records per selected file, at most 4,800,000 decompressed bytes per prefix. Full compressed object identity is retained; later records/frame content are not semantically validated or used. Require all six complete prefixes, no clock regression under the recorded working interpretation, and preserve ties, zeros and every request. No interpolation, request thinning, outcome-based truncation or dropping inconvenient files. Do not interpret count-block horizons as equal elapsed time. Report first/last raw clocks and zero-size/tie/unique-prefix counts without using them to select models or cohorts.

For each file map each opaque object token to its zero-based ordinal of first appearance and publish only that ordered 200,000-ID sequence in deterministic gzip JSON, plus aggregate quality/provenance. Preserve complete originals privately; exclude raw addresses/identities, exact request clocks/sizes, host/client/IP details and future fields. Independent native verification reopens exact private objects, reconstructs fields with a separate byte parser and verifies every ordinal/quality count and file hash. Public replay can reproduce simulations from the transformed sequence. This is a documented transformation of licensed traces, not a synthetic workload or an anonymity guarantee.

## Volume, sequence and configuration separation

Assign six trace IDs by ascending SHA256(trace_id), alternating three development and three final before GET. Each prefix contains 200 complete blocks of 1,000 requests, indexed0..199. The LRU simulation begins empty at the prefix start. Every request touches an object regardless of source size; equal-object slots deliberately ignore byte occupancy, read/write semantics, admission, prefetching, parallelism and actual storage layers.

Development: capacity 512 slots throughout. Fit on blocks3..119 of each of three development volumes (three prior block miss counts available), expected 351 training origins. Validate on blocks120..159 of those volumes, expected 120 origins. Blocks160..199 of development volumes remain unused. Final: other three volumes only, score blocks160..199, expected 120 origins per scenario. Model features at block t are only the prior three completed block miss fractions (t-1,t-2,t-3), known before t begins. Never current-block outcomes, file-level future summaries, oracle values or final-volumes fit data.

Three final scenarios share the same source request prefix and capacity 512 through block 159. At the boundary before block 160: control remains 512, shrink changes to 128, expand changes to 2048. Preserve actual resident state; shrink immediately evicts oldest entries until within capacity; expand does not resurrect previously evicted objects. Simulate all requests in the prefix to supply valid history. No cold restart at the change. Model and baseline receive no capacity indicator or configuration-change feature. These are configuration-blind forecasts whose transfer failure is the question, not a policy recommendation to hide a known change.

No final-volume cache simulation, miss counts, forecast features, targets, scores, plots or summaries before dependency freeze. Raw source/projection validation may see final request IDs; collection is not blinded and not an original-vintage deployment forecast. Freeze protocol/source/assignment/prefixes, model/simulation/checker/exercise code, tests, all development candidates/results and selection before final extraction. A necessary later analytic correction preserves originals and makes reused final evaluation retrospective; no final-driven parameter changes.

## Models, selection and outcomes

Baseline predicts the previous completed block's miss fraction. Candidate forecasts are pooled linear autoregressions with intercept and three lag fractions. For X with leading intercept and y miss fraction, solve (X'X + lambda*diag(0,1,1,1))*beta = X'y. Fit with exact Fraction normal equations and a four-by-four pivoted elimination; intercept unpenalized, no scaling or hidden optimizer. Positive lambda in {0.01,1,100} is an authored finite sensitivity grid, not inherited defaults or a global optimum. With the fixed training count, document the normal-equation penalty convention; it is not lambda times n. Clip forecasts to[0,1], retain unclipped values and clipping counts.

Keep every candidate's coefficients, predictions, validation scores and execution runtime. Select exact smallest validation MAE averaged equally across the three development volumes; exact ties choose the larger lambda. No validation refit. The previous-block baseline is reported without being a tunable candidate. Fixed expected origins, not missing-as-zero denominators; unavailable inputs fail dependent evaluation rather than reduce criteria.

Final primary outcome: MAE in miss-fraction units averaged equally over the six changed-volume/scenario groups (three volumes times shrink/expand). Report each scenario and each volume, micro MAE, MSE, signed error, clipping counts and baseline differences. Separately report the matched control groups and the first five post-change blocks as a prespecified transient view. Report target count means and paired simulation changes versus control without claiming measured system effects. Preserve a baseline win, all ties and every worse group. Shared prefixes/scenarios and overlapping lag features are dependent; no independent-sampling interval or causal generalization to production.

Independent simulation uses a dictionary plus a min-heap of last-access indices, not the OrderedDict implementation. Verify every request/block and dynamic resident-state behavior. Independent regression uses NumPy 2.2.5 solve from separately reconstructed lag arrays, coefficient absolute tolerance 1e-8, prediction tolerance 1e-9 and metric tolerance 1e-10, plus rational recomputation of saved exact metrics and selection. Do not import fitting/simulation metric helpers. A discrepancy is a gate failure, not nudged data or relaxed tolerance. Fixtures include cold starts, repeated requests, eviction order, shrink, expansion without resurrection, zero capacity rejection, count-block boundaries, no-future-label features, future-byte mutation invariance, source-prefix truncation, regression ties/constant histories, clipping and missing exercise input.

## Practical use and boundary

Offline exercise accepts three completed authored block miss counts, a declared known configuration-change context and the frozen model. It returns transparent baseline/candidate estimates and recommends collecting post-change history when context changed. It changes no cache, sends no alert/message and makes no source request. Its estimates are teaching outputs under this simulation, not capacity recommendations, hardware forecasts or measured operational benefits.

A planner should record configuration boundaries and recheck a forecast against a simple baseline before relying on it. Actual deployment decisions need byte-aware cache behavior, real I/O operations, timing, concurrency, production measurements and verified costs. No new estimator, scientific-priority, energy/latency/savings, adoption or production-readiness claim.
